# Lab figures

Generated by `tools/make_lab_figures.py` from `lab/REPORT.json` and `lab/EXTRAS_ens4d.json`.
Nothing is re-run: every value plotted here is read straight out of those two JSON files.

Regenerate everything with:

```
uv run python tools/make_lab_figures.py --report lab/REPORT.json --extras lab/EXTRAS_ens4d.json --out docs/paper/figures --split-label "test split"
```

## Figures

### fig_methods_by_scale

Dumbbell plot of raw vs chosen-calibration accuracy for every method, one panel per degradation scale; methods are ordered top-to-bottom by mean chosen-calibration accuracy across the five scales. The dashed line marks the project's 0.85 accuracy target.

- Input file(s): REPORT.json
- Files: `fig_methods_by_scale.png`, `fig_methods_by_scale.pdf`

### fig_learning_curve

Accuracy vs number of labeled examples used to fit the per-scale calibration, one line per degradation scale with a ±1 sd band over random draws; n=0 is the uncalibrated (raw) readout.

- Input file(s): EXTRAS_ens4d.json, REPORT.json (for the held-out n in the subtitle)
- Files: `fig_learning_curve.png`, `fig_learning_curve.pdf`

### fig_accuracy_vs_cost

Accuracy vs cost (forward passes). Diamonds are ensembles; every other method is a circle.

- Input file(s): REPORT.json
- Files: `fig_accuracy_vs_cost.png`, `fig_accuracy_vs_cost.pdf`

### fig_accuracy_vs_latency

Accuracy vs latency. Diamonds are ensembles; every other method is a circle.

- Input file(s): REPORT.json
- Files: `fig_accuracy_vs_latency.png`, `fig_accuracy_vs_latency.pdf`

### fig_transfer

Heatmap of accuracy when a calibration fit on one scale (row) is evaluated on another scale (column); POOLED and NONE (raw) rows are included for reference.

- Input file(s): EXTRAS_ens4d.json
- Files: `fig_transfer.png`, `fig_transfer.pdf`
